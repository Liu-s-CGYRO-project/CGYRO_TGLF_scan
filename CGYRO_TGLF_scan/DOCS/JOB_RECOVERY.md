# OMFIT 退出后按作业号恢复

适用于由本工程提交的 Slurm CGYRO 扫描。VNC 桌面关闭后，先查询原作业；OMFIT 窗口消失不代表计算失败，不要直接重新运行整批。

## 操作

1. 重新打开原工程，在“运行与环境”中选择原来的服务器，并应用连接配置。
2. 进入 **CGYRO 扫描 → 结果与记录 → 恢复已提交的作业**。
3. 输入主作业号，例如 `9817420`，点击 **按作业号恢复**。数组作业使用主号，不填 `_0` 等子任务后缀。
4. 运行中的作业使用 **同步作业状态**。已结束、失败或被取消的作业使用 **重新收集未归档结果**，读取仍然存在的输出。
5. 收集完成后查看数值表或时间曲线，需要进一步计算时再明确选择点续算。保存工程以保留恢复记录。

恢复只接回任务记录及原始输入，不会重新提交、取消或等待远端计算。Slurm 的 `COMPLETED` 表示作业退出成功，不保证每个点都已达到求解器收敛条件。

## 旧任务的扫描清单

新版提交前将 `.cgyro_recovery.json` 与输入一起上传。它只保存扫描身份、坐标、校验和及运行元数据，没有计算结果。即使 OMFIT 未保存即退出，仍可由作业号找回。

旧任务通常只有 OMFIT 暂存目录中的 `manifest.json`。恢复模块在原服务器的当前用户 OMFIT 会话目录中按运行 token 查找，不递归扫描结果数组。查找失败时，勾选“指定旧清单位置”，填写**该服务器上**原清单的绝对路径。清单已删除时停止，不使用当前 GUI 参数猜测旧扫描。

服务器仍须提供作业的队列或记账记录、原运行目录、提交回执和脚本。模块核对登录用户、作业号、目录、脚本摘要、扫描坐标及下载输入的校验和。身份冲突时保留工程现有记录。

## 结果与续算

输入及计算结果仍由 `RUN_DB` 管理，`RUN_HISTORY` 和 `RUN_MANIFEST` 只保存元数据。已有公开扫描不因恢复而改变；收集时沿用按完整参数坐标和 ky 合并的规则。

可依次恢复多个作业，未收集的原记录仍在队列中。重复恢复同一已保存作业不重复下载输入或创建第二份结果。已经被新运行替代并清退载荷的旧记录不重新导入。

原输入 ZIP 缺失时仍可接回可收集的输出，并列出缺失点。没有结果也没有原输入的点无法凭作业号重建。续算任务依赖源运行的冻结记录，需先恢复源运行，再恢复续算任务；检查点和历史一致性校验仍有效。

## 脚本入口

设置好原服务器连接后，也可在 Command Box 执行完整一行：

```python
OMFIT['CGYRO_TGLF_scan']['CGYRO_scan']['SCRIPTS']['recover_job.py'].run(job_id='9817420')
```

自动查找失败时增加 `manifest_path='/原暂存目录/manifest.json'`。该入口与按钮共用同一套检查。
