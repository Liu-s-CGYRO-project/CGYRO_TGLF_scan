# CGYRO 结果存储与按需读取（1.24.26）

RUN_DB 是 CGYRO 结果的唯一来源。TGLF 使用原生 scanResults / scanResults2D / scanResults3D 等结构，详见 TGLF_RESULT_STORAGE.md。普通扫描放在结果名/半径/参数组下，H/D/T 在对应离子分支；BASE/KY_ONLY 只保存原始参数基准。不同参数和带符号 ky 是不同计算点。

CGYRO 扫描设置可选一个 constant 固定参数，例如扫描 N_THETA 时固定 BETAE_UNIT=0.0001。固定值实际写入每个点的 input.cgyro，并记录于现有清单、扫描索引和结果身份中；物理分组名称为 `nr=1_rho=0.33_BETAE_UNIT=0.0001`，原始离子扫描直接放在该分组下，H/D/T 使用各自子分支。更换固定值产生独立分组，普通列表只读这些头信息；绘图、按作业号恢复及续算使用完整分组身份。续算取所选结果保存的值，不取当前 GUI 的值。此项与“计算参数”共用 fixed_parameters 中的数值，不另存第二份输入设置。未启用时保持原布局；现有结果保留原有位置，更新无需全库迁移或重新收集。

每个点收集时记录求解器状态、最后模拟时间、样本数、检查点可用性和文件大小。切页、筛选和选择只读这些索引摘要，不打开全部结果。结果列表读取扫描名称；选中后才读取当前扫描的点摘要。绘图、时间平均和续算只读取所选范围。数值表列出实际统计窗口，改变平均比例后重新计算。

同一完整参数坐标只保留当前有效结果。实际参数优先从 input.cgyro.gen 比较，包括精度容限等；MAX_TIME 等运行控制不拆分坐标。新扫描下载、核验完成后替换同坐标旧结果；续算优先保留已收敛或模拟时间更长的有效结果。失败续算不能覆盖正常旧结果，尚未处理输出单独保留。未选择的其他参数点不受影响。

更新到当前 1.24.28 时保留结果和设置，重新打开结果窗口即可。旧摘要缺失显示待校验，使用对应点时才补查；不需要为修复续算先执行全库整理。身份确实不明的点会单独报告，文件保留。

只有主动整理旧工程、去重或回收无引用文件时，才执行维护入口并另存：

```python
OMFIT['CGYRO_TGLF_scan']['SCRIPTS']['compact_cgyro_storage'].run()
```

删除任务记录与删除结果引用分开；物理文件仅在明确维护并确认没有任何结果或待处理任务引用后回收。原工程 ZIP、原目录与服务器文件不删除。

普通收集不计算全工程空间总量，也不回收整个物理池。替换后的旧引用解除，无引用文件等到显式维护确认没有结果或待处理任务引用后再清理。旧工程缺摘要时可以显示未计数/待校验，不为补齐列表数字遍历其全部点表。

## 检查点选择与 .old 风险

结构检测涵盖 v3 文件头、端序、网格尺寸、载荷长度、有限值和配套时间标签；摘要复查文件没有在读取期间变化。报告在 `RUN_DB/__STORAGE__/checkpoints`。

当前 `bin.cgyro.restart` 通过检查且配套 tag/time 一致时，归档副本只保留当前文件，省略 `.old`。当前损坏而 `.old` 结构有效时，保存 `.old` 作为备份。无法确认时保守保留两份，并报告原因。

省略 `.old` 会失去回退上一检查点的机会：以后当前文件发生存储损坏，或求解器实际读取才暴露问题时，这份新工程中没有上一份备份。结构与有限值检测不能发现所有静默损坏，也不证明求解器一定能读取。原 ZIP 和来源文件仍保留，因此可以另外找回旧备份。

只剩 `.old` 时，当前 `out.cgyro.tag` 不一定与它对应；不会自动把它提升成可续算的当前检查点。没有相配的历史标签与时间序列，续算会要求核对，不冒用当前时间。也不通过补偿物理参数掩盖重启问题。

已用太原原生类在独立小工程验证共享文件保存与 ZIP 重开；用户完整工程 GUI 和集群续算不属于该夹具验证范围。依据为上游 `cgyro/src/cgyro_restart.F90`，完整维护约定见仓库 RESULT_STORAGE_DESIGN.md。

## /tmp 100 GiB 限制

每批运行开始准备输入时，仅检查一次已有临时占用是否不超过 100 GiB；H/D/T 后续案例不重复遍历。标准 `/tmp/<user>/OMFIT/...` 按 `/tmp/<user>` 汇总会话。运行中的临时峰值允许超过 100 GiB，不把另有的 100 GiB 余量设成新硬上限。每次准备、打包、复制、下载及归档仍检查目标文件系统的真实剩余空间。手动收集和整理不因已超过启动阈值而拒绝执行；空间不足时停止新增复制，保留 RUN_DB、原 ZIP 和远端身份。不持久化“已经检查”的开关；每次新的运行或续算重新执行启动检查。

输入打包后核对 ZIP 成员及 SHA-256，只清理本轮 `runs/<UUID>/staging/pNNNNNN` 展开目录。显式整理也会检查已保存运行的这类目录。含软链接、校验不一致、仍被结果读取器引用的目录保留并报告；不按日期扫描删除整个 /tmp，也不清理其他项目或 OMFIT 的物理所有者。关闭或另存工程后，框架自身目录的回收仍由 OMFIT 管理。

## 归档提示 prior parameter/ky coordinate（1.24.17 修复）

1.24.16 及更早版本在保留旧 ky、合并新增计算点时，可能误把重建的浏览链接判为结果变化，从而阻止归档。该异常发生在合并校验阶段，不代表需要重新计算；成功的作业和已有结果仍由原流程保留。

更新代码，关闭旧设置窗口再打开，然后点击“重新收集未归档结果”。手动收集只读取已有输出，不提交新任务。新版按已验证的结果摘要校验，真正缺失旧点或替换其他扫描的结果仍会中止；不通过跳过保护来让归档成功。
