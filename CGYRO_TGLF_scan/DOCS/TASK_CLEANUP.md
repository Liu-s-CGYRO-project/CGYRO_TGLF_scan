# 按任务删除 CGYRO 记录和结果

打开 **CGYRO 扫描 → 结果与记录 → 任务管理 / 删除任务…**。

1. 输入作业号查找，也可按服务器、半径、离子或扫描参数筛选。
2. 选择一条或多条任务。列表同时包含已归档、未归档、部分输出，以及尚未取得作业号的任务；默认不选择任何任务。筛选或刷新后会清空选择，“全选当前列表”只选择可见行。
3. 默认只删除任务记录；需要删除结果时，勾选“同时删除所选任务的归档结果引用”。点击“删除所选任务…”。第一次确认逐项列出完整任务标识、服务器、全部关联作业号和归档点数，可滚动核对。第二次直接点击确定执行删除，无需输入或复制确认文字；默认选择取消。任一次取消或关闭窗口均不删除。
4. 删除成功后另存工程；原先已保存的 ZIP 不会被改写。

每行对应一次扫描提交及其自动重试。自动重试共享冻结输入和任务身份，因此作为一组删除，全部重试作业号均会列出；续算使用独立任务身份。相同作业号出现在不同服务器时是不同记录，不能只凭数字判断。这里删除整个所选任务，不是删除某个 Slurm 数组子作业。

## 实际删除范围

- 默认删除所选任务的记录、冻结输入与未归档输出引用，公开 RUN_DB 结果保持不变。勾选结果删除后，才解除仍由这些任务拥有的公开点引用。
- 同一扫描参数下属于其他任务的坐标和带符号 ky 保留；同一坐标已由新任务替换时，不随旧任务删除。其他扫描参数、半径、离子和结果集保留。
- 此操作只解除引用，不立即清理物理所有者。显式维护时再检查全部结果和待处理任务的引用；共享文件仍有引用就保留。身份不明的旧节点不会按目录名称猜测删除。混合索引存在歧义时中止整个操作。
- 远端作业继续存在；不执行 `scancel`，不删除服务器目录、原始输入、已有 ZIP 或 /tmp 文件。需要停止计算时先使用独立的取消作业入口。

本地正在提交/收集、身份冲突，或确认期间相关任务/结果变化时阻止删除。历史关联不阻止删除，保留的 RUN_DB 结果仍可直接续算。异常或 Abort 时回滚元数据；物理所有者不在此操作中变更。

内部仅保留已删除任务标识的布尔标记，用来拦截旧窗口和 finally 回调重新写入记录；不保留该任务的作业详情、数值结果或恢复快照。若以后确实需要重新导入，可显式“按作业号恢复”，完成原始身份和输入核验后再接回；普通旧窗口不能恢复已删除任务。

“删除指定半径…”仍可用于明确删除整个半径；它同样需要两次确认。只删除一个任务时应使用任务管理界面。

## 程序接口

`preview_tasks(cgyro_module, tokens, delete_results=False)` 返回具体删除范围、元数据 revision 和本次内部确认凭据；不启动求解器，不读取数值数组。旧格式元数据在生成预览前按现有 RUN_DB 契约规范化。

`remove_tasks(cgyro_module, tokens, expected, confirmation, factory)` 在写入前重新规划并比较完整预览，只接受对应内部凭据。GUI 在两次点击确认后自动传递该值，不要求用户输入。原生入口为 `CGYRO_scan/SCRIPTS/remove_tasks.py`，默认 `confirm=False` 仅预览；GUI 通过 `ProjectActions.remove_cgyro_tasks` 调用，保留 OMFIT 的日志和 Abort 行为。

`tokens` 是列表中的完整任务标识，不是任意路径或作业名称。空列表不表示“全部”，未知或重复任务标识均拒绝。不要绕过预览直接修改 RUN_DB 的索引或物理所有者池。
