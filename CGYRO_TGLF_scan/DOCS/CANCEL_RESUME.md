# 取消、收集和继续计算

## 提交时 Abort 后

工程 1.22.36 也将上传 / 提交窗口的 Kill local 接入停止流程：保存停止意图，找回已接受的作业后取消本批已确认任务并收集；回执不明时保留保护，可稍后同步。原生 Abort 仍中断本地脚本，不等于取消 Slurm。直接关闭整个 OMFIT 无法自动收集，重开后先同步再收集。

重复收集部分结果时中断，原恢复入口仍保留；跨重试保留各点取消 / OOM 状态。旧记录无提交脚本摘要时禁止自动重提，可明确选择点续算。完整审查与限制见 [流程审查](https://github.com/Liu-s-CGYRO-project/CGYRO_TGLF_scan/blob/main/WORKFLOW_AUDIT.md)。

输入上传与调度提交分开记录。“上传输入中”阶段只传文件，不执行 sbatch / qsub；此时 Abort 可直接重新运行。提交阶段中断仍保留回执和原目录。失败点重试若未提交成功，恢复上次已确认的作业与结果来源，不把成功点指向空重试目录。

点击“同步作业状态”先读取原目录日志；缺少回执时按原服务器、原 WorkDir 查询当前队列及最近七天账目。仅恢复唯一匹配的数组主作业号；多匹配、查询失败或旧记录无匹配时继续保护。此查找遵循 [squeue](https://slurm.schedmd.com/squeue.html) 的工作目录 / 数组主号字段和 [sacct](https://slurm.schedmd.com/sacct.html) 的 WorkDir 字段。

新提交在登录初始化后显式进入原目录，校验本轮标识，独占创建提交入口目录后才调用调度器。恢复若先取得该入口并写下本轮封闭回执，即证明这一轮未提交且迟到命令不能再提交，可解除保护。已有入口不删除，不取消已接受作业。同步此时只写小型提交标记，不修改求解器文件。

旧版本没有这个入口，日志不存在不能自动解释为未提交。先检查原服务器的队列和账目；人工核对后可仅解除指定 token 的本地待确认状态，并保留原状态与核对依据。不要清空 RUN_MANIFEST、归档或其他案例。Abort 会继续向上传播并停止后续提交。

## 手动重新收集

工程 1.22.35 起，“重新收集未归档结果”和“收集 CGYRO 当前结果”只查询原作业、读取 / 重读已有文件并归档，始终禁止求解器补算，不受“失败点重试次数”影响。失败点和未推进点保留当前状态；需要继续计算时，由用户选择点后明确提交续算。

手动批量收集遇到仍在运行的案例，会报告该案例尚未结束，继续处理其他案例，不进入等待作业结束的循环；活动输出不在写入中读取。下载或解析失败仍允许有限次重读文件，这与提交计算分开。正常“运行所选扫描”和用户发起的续算，仍按配置使用原失败点重试机制，取消后禁止补提。

更新不取消旧版已经提交的补算。已有作业仍使用原作业号和目录管理，结束后可以重新收集。

## Kill local 后

Slurm 等待窗口沿用原 Kill local：核对保存的作业号、token、服务器和工作目录，取消本批尚未结束的作业，停止本地等待，然后自动收集所有已提交案例。不新增取消按钮，不修改 OMFIT 本体。取消只是请求，需等 Slurm 确认终态；记账延迟或连接失败时保留记录并说明，可稍后同步、重新收集，不能据此重复提交。

收集按点判断。只有输入或缺少必要输出的点直接跳过；能读取的正常完成点与部分时间样本分开记录。下载或解析异常仍保留错误，允许有限次只读重试；不把连接失败当作没有结果。取消后禁止失败点自动重提。

完整扫描仍替换相同案例的相同参数组。部分扫描进入原结果名后的 [partial token] 独立记录，保留原完整结果；无可读结果时不创建空 RUN_DB，原输入和点表保存在运行历史。“结果记录”可以选择部分结果或“无结果，可恢复”的记录。批量摘要分别显示完整、部分和无结果跳过的案例数。

## 大扫描收集失败后

若旧版提示 `/bin/bash: Argument list too long`，输出探测脚本未执行，不能据此判断计算失败或结果丢失。更新到工程 1.22.27 后点击“重新收集未归档结果”，复用保存的作业号和目录，不要重新提交扫描。本版共用点检查函数，并按转义后的命令字节数分批检查，记录已检查点数和失败批次。全部批次返回完整点表后才读取结果；中断仍可重新收集，已归档结果保留。

## 续算尚未超过旧末时刻

工程 1.22.34 起，可读且历史前缀一致的续算，即使尚未超过旧结果末时刻，也按“续算待推进”保存到独立的部分归档；不再报成下载失败，不阻断其他可读点归档。原完整扫描保留。检查点有配套历史且验证有效时可继续使用；再次续算仍以来源链中原先的最长末时刻为目标，不因某段较短而降低完成条件。只有历史截断、前缀改变或读取异常仍报告错误。

升级时保留案例、运行记录和设置，重新打开总控，点击“重新收集未归档结果”即可重读已结束作业；不必重新提交整批。结果记录切换到本次部分结果后，在时间曲线与续算窗口查看具体点、末时刻、检查点和原因。该提示本身不代表新增了超过旧结果的数据，也不代表求解器已收敛。

点表同时列出该点实际 Slurm 状态。OUT_OF_MEMORY 需先检查该点日志与 Slurm 资源配置，延长 MAX_TIME 或墙钟时限不能解决内存不足；FAILED 需结合本点日志分析。数组编号对应本次冻结点表的顺序，续算子集的数组编号不能直接当成原 p 点号。自动重试不处理内存不足、取消或超时，也不因“续算待推进”本身自动重提。

## 选择点并继续

在“结果与记录”选择本次记录，打开“ω、γ 随时间变化 / 选择 ky 续算…”；完全没有结果时使用“选择未完成点继续计算…”。默认勾选可继续的未完成点，完整完成点默认不选，也可手动调整。选择后填写追加时间 Δt，点击“继续计算所选点”。

| 计算点情况 | 行为 |
| --- | --- |
| 有有效检查点和配套历史 | 复制到新的运行目录，从检查点追加 Δt；核对时间标签、历史前缀和实际进展 |
| 上一次续算尚未开始 | 可复用原准备 ZIP 中的检查点；解包时再次校验原 SHA-256 |
| 确认没有时间样本且原来是新算 | 使用保存的原始输入 ZIP，新目录从头计算；MAX_TIME 为原值加 Δt |
| 已有样本但缺少或损坏检查点 | 明确提示并停止，不能静默从零开始 |
| 缺少原输入 ZIP 或校验不一致 | 停止并保留原结果，不能从当前参数界面重建历史输入 |

各点均使用冻结的实际参数、ky、时间缩放和物种输入，不重新套用后来修改的 GUI 参数。原服务器和检查点执行环境需一致；墙钟时限可在环境配置中延长。重算或续算只在用户明确提交后发生，取消后的自动收集不会提交新作业。

继续计算后保留原来已完成且未选择的点。只有覆盖原计划的全部完成点，才把新结果作为完整扫描；仍有空点或部分点时继续单独归档。再次取消会保存本次和上次运行的来源链，下一次按最新有效检查点或原输入继续，旧取消标记不带入新运行。

Slurm 的取消状态、结果收集状态和求解器收敛是三件事。COMPLETED 或成功退出不保证已达到所需数值精度；“选择到时未收敛点”和时间曲线仍可用于检查。CGYRO 官方列出的重启数据为 out.cgyro.tag 与 bin.cgyro.restart，重启还需配套历史，参见 [CGYRO 输出说明](https://gacode.io/cgyro.html#output-data)。

## 校验范围

本版仅完成 Python 3.9 AST / 符号、OMFIT 原生接口与库登记、取消 / 重试 / 归档 / 再续算的源码路径审查，以及安装包字节、CRC、SHA-256 与小于 1 MB 的检查。未运行测试、GUI、实际下载或提交集群作业，真实 Slurm / 文件系统行为仍需用户环境验证。
